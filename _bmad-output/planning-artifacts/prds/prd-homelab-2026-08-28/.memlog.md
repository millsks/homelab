- (assumption) Outlet constraint found: BR1500MS2 has 10 outlets but only 5 battery-backed, vs 6-7 devices needing backup. Resolution: non-surge power-distribution strip on one battery outlet feeding the 4 mini-PC bricks (~200W). Cascading surge suppressors is an anti-pattern. Switch MUST be battery-backed or NUT clients lose network before the shutdown signal.
- (decision) UPS FINAL: APC Smart-UPS SMT1500C (1500VA/1000W, pure sine, 8 outlets ALL battery-backed, hot-swap battery). Third and final selection - BX1500M rejected on waveform, BR1500MS2 rejected on outlet topology (5 battery of 10 vs 6 required). Smart-UPS resolves outlet count structurally; distribution strip no longer needed.

- (decision) FR-23 credential caching KEPT and reframed - not a defense layer traded against break-glass, just a single SSSD setting. Value is working as one's own Account during an outage, and Guests staying functional.
- (decision) FR-25 Directory replica KEPT, justification corrected: it is about SERVICE availability, not login. Directory is a runtime dependency of the IdP and therefore every Relying Party; single instance makes every Directory patch a platform-wide SSO outage. Sequenced to the deepen phase, not the Walking Skeleton, so it stays a clean cut if deferred to v2.
- (change) FR-24 further amended: Break-glass home must not only be local but must lie OUTSIDE any NFS-managed path. A local home nested under the Share mount point is shadowed while mounted and invisible under autofs - local is necessary but not sufficient. Architecture must place it at e.g. /var/local/<name>.

- (decision) NEW FR-65 (number reused): Nodes and Nidavellir wired-Ethernet only, wireless DISABLED not reserved. Rationale: corosync cluster membership is latency/jitter sensitive; wireless variance reads as node loss and causes spurious partitions and evictions. Silent WiFi failover is worse than no WiFi. NFS degrades badly on lossy links.

Nidavellir on a 2.5GbE port despite 1GbE nodes - 4 nodes can demand ~4Gbps aggregate, so the faster shared-side link is free value.

Rationale: USB Ethernet is prone to resets/renumbering; acceptable for traffic that retries, not for the signalling that decides whether a node is alive.
